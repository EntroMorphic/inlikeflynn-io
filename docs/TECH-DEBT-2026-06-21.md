## 🔴 TD2-1 — `three.min.js` has no Subresource Integrity, and defeats offline

**Evidence:** 10 pages load `https://unpkg.com/three@0.149.0/build/three.min.js`
**without `integrity` or `crossorigin`** (the only external dep on the live site;
`grid-void.js` references `THREE` 68×). The Babel/React CDN tags *do* carry SRI — but those
now live **only in `index_v1.html`** (see TD2-2), so the live site's sole CDN script is the
un-pinned one.

**Why it hurts:**
1. **Supply chain / security** — if unpkg serves altered bytes, arbitrary JS runs on every
   page. No integrity check, no CSP backstop.
2. **Offline / PWA** — the site ships a service worker and an INSTALL button, but the hero
   grid's `three.min.js` is fetched from a third party and **isn't in the SW precache**, so
   the 3D grid won't render offline until/unless that cross-origin request happens to be
   runtime-cached.

**Fix (preferred):** vendor `three.min.js` into `assets/js/` (pin the version), reference it
locally, and add it to the SW precache. Removes the external dependency, fixes SRI, and makes
the grid genuinely offline-capable. **Alternative (min):** add `integrity="sha384-…"
crossorigin="anonymous"` to the existing CDN tag.

## 🟡 TD2-2 — `index_v1.html` is keeping a dead toolchain alive

**Evidence:** `index_v1.html` is the **only** referrer of `tweaks-panel.jsx` (25.8 KB),
`tron-tweaks.jsx`, `tweaks.jsx`, **and** the in-browser Babel + React CDN scripts
(`@babel/standalone`, `react`, `react-dom`). The live site dropped the Tweaks panel; those
files are dead weight kept "reachable" only by this one snapshot. `index_v1.html` itself is a
public copy of the old landing (its `<link rel=canonical>` correctly points to `/`, so
duplicate-content risk is low, but it's not `noindex` and not disallowed in `robots.txt`).

**Fix:** remove `index_v1.html` and the three orphaned `.jsx` files (and the Babel/React CDN
tags die with them) — this finally retires the in-browser-Babel concern from the v1 audit. If
the snapshot must stay for reference, move it under the git-ignored `backups/` (it's already a
convention here) or add `<meta name="robots" content="noindex">`.

## 🟡 TD2-3 — 3 public pages lack social/canonical metadata

**Evidence:** coverage matrix — `case-for-flynn.html`, `flynn-overview.html`,
`flynn-overview-bd.html` have only `<title>` + `meta description`; **no `canonical`, no
`og:*`, no `twitter:*`.** Every other public page has the full set.

**Why it hurts:** `case-for-flynn` is a shareable sales page — pasted into Slack/LinkedIn/
iMessage it renders as a bare link (no card image/title/description). No canonical also leaves
duplicate-URL ambiguity.

**Fix:** add the standard OG/Twitter/canonical block (copy the pattern from `why-flynn.html`),
with page-specific `og:title`/`og:description`. The overview/BD infographics may stay minimal
if they're deck-only — owner's call.

## 🟡 TD2-5 — ~2.8 MB of unoptimized PNGs

**Evidence (heaviest):**

| File | Size | Used by |
|------|------|---------|
| `screenshot-wide.png` | 915 KB | manifest screenshot |
| `og-flynn.png` | 758 KB | OG/Twitter share image |
| `screenshot-narrow.png` | 750 KB | manifest screenshot |
| `icon-512.png` | 452 KB | PWA icon |
| `flynn-scope.png` | 375 KB | overview pages |

No WebP/AVIF anywhere. The manifest screenshots + scope image are the worst offenders.

**Fix:** compress (oxipng/pngquant) and/or convert to WebP where a PNG fallback isn't required
(scope image, manifest screenshots support WebP). Keep `og-flynn` as PNG/JPG per OG conventions
but it can shrink a lot. Realistic savings: 50–70%.

## 🟢 TD2-6 — `bump-cache.mjs` fragility

**Evidence:** this very drop shipped **non-uniform `?v=`** — 86 tags bumped, 21 left stale on
`case-for-flynn` / `flynn-overview(-bd)` / `index_v1` — which **fails the CI cache check**
(caught and completed during deploy). Separately, `bump-cache.mjs` walks the git-ignored
`backups/` tree and stamps archived copies.

**Fix:** the CI gate already catches non-uniformity (good — keep it). Make `bump-cache.mjs`
skip git-ignored paths, and treat "run bump-cache as the **last** pre-export step" as the
canonical flow (already noted in `CONTRIBUTING.md`). Root cause was a partial run, not the
tool's coverage (it does recurse all `.html`).

## 🟢 TD2-7 — Residual inline-CSS shared layer

**Evidence:** 4,049 lines of inline `<style>` across pages; **~199 redundant rule copies**
repeated on ≥3 pages — now clustered around a shared page-chrome layer: `.page-head`,
`.page-head h1`, `.strip-row span(::before)`, the `*` reset, and shared `@keyframes`
(`from`/`to`). This is the same *category* TD-1 addressed, re-emerging in the newer pages.

**Fix:** extend the established pattern — lift the byte-identical page-chrome atoms into
`infographic.css` (or a small `base.css`), keeping genuinely page-specific CSS inline per the
TD-1 decision. Secondary; the bulk is intentionally-tuned per-artifact CSS.
